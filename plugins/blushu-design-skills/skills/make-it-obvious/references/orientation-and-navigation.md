# Orientation and navigation

Use this reference for multi-page products, home or landing pages, deep links, persistent and local navigation, search, and location cues. Review arrival from outside the intended path, not only a journey beginning at the home page.

## Deep-entry orientation test

Open a representative lower-level page without showing prior steps. Check whether a new arrival can locate, quickly and without close study:

1. product or site identity;
2. current page or state name;
3. major sections or global destinations;
4. choices available at the current level;
5. current location in the larger structure;
6. search, when the content scale or user behavior makes it necessary.

Record missing cues separately from cues that exist but are too subtle to work. A cue that requires the reviewer to explain it has failed this test.

## Identity and page naming

- Keep product identity persistent enough to orient an external arrival.
- Place the page name so it frames the page-specific content rather than navigation or promotions.
- Make the name visually behave like the top-level heading for that state.
- Match the destination name to the link or action that led there. Accept small wording differences only when equivalence is immediate.
- Do not treat a highlighted navigation item as a substitute for a page name when the page still lacks a clear content identity.

## Global and local navigation

Distinguish navigation roles before critiquing their appearance:

- **Global:** stable access to major product areas.
- **Local:** options within the current section or object.
- **Utility:** account, help, cart, settings, contact, or other supporting destinations.
- **Contextual:** actions or related destinations tied to current content.

Check that visual prominence reflects these roles. Do not let utilities overwhelm primary sections. Inspect every supported depth, not just the home and second level; ad hoc lower-level navigation produces orientation failures late in the task.

Use persistent navigation when repeated access and reorientation justify it. Do not require identical navigation on focused transactional steps if removing it protects completion and an obvious exit or recovery path remains.

## Location and return paths

- Make selected section and subsection cues conspicuous enough for rapid scanning.
- Use more than one distinction when color, weight, or position alone is too subtle.
- Provide a reliable route to a stable starting point or higher level.
- Use breadcrumbs for deep, hierarchical content when moving upward is common.
- Treat breadcrumbs as structure, not browsing history; omit them when the model is not hierarchical.
- Keep the current breadcrumb item non-interactive and visually distinct from ancestor links.

Do not add location indicators that introduce more noise than orientation value in a shallow product.

## Search and browse

Account for both search-first and browse-first behavior.

- Make browse categories reveal the product's actual content structure and use task language.
- Provide search when the corpus is large, heterogeneous, or known-item retrieval is common.
- Make search look and read like search; avoid novel labels that weaken recognition.
- Defer scope and advanced filters until results show they are necessary, unless scope is essential to prevent a costly error.
- Preserve the query and make empty, partial, and error states explain what happened and what to do next.

Search does not excuse poor navigation, and navigation does not excuse missing search when direct retrieval is a primary behavior.

## Home and landing comprehension

Verify that a first-time visitor can determine:

- what the product or organization is;
- what it enables or contains;
- why the current visitor might use it;
- where to start the primary task, browse, search, sign in, or register as applicable.

Use the entire composition as evidence, not only the tagline. If explicit explanation is needed, keep it prominent and only as long as required. Do not replace a concrete value proposition with a generic mission statement or motto.

Separate two possible problems:

- **Concept failure:** the visitor cannot form a correct model of the offering.
- **Entry failure:** the offering is understood but the first action is obscured.

Merge them only when one element or hierarchy failure causes both.

## Validate orientation

Choose validation according to uncertainty:

- **Brief exposure:** show the screen for a few seconds, hide it, and ask what it was and where to begin.
- **Deep-link task:** start at a lower-level page and ask the person to explain location and next options.
- **First-click task:** give a goal and record the first selected destination plus confidence.
- **Return task:** ask the person to move upward, return home, or recover from a wrong turn.

Do not infer success because all navigation elements are technically present. Validate whether their roles and current state are perceptible.
